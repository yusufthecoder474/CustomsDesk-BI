# Power Query guide

Start with powerbi/parameters.md and fxLoad.m. Each table .m file calls the shared loader. It supports
PostgreSQL navigation through public schema and UTF-8 quoted CSV import. It validates object names,
normalizes text whitespace and empty values, enforces dates/durations/flags, converts timestamps
to UTC before removing the zone for the model, and preserves HS values as text.

SourceMode is exactly CSV or PostgreSQL. ExportFolder is an absolute directory without a trailing
backslash. Refresh updates imported snapshots; it does not trigger Python ETL. Rerun ETL and export
first. Refresh is manual; no gateway/Power BI Service deployment is supplied.

Do not use Remove Errors to hide bad rows: diagnose schema/type changes and rerun validation.
Null response hours have analytical meaning and must not become zero. Missing hs_code remains
null while code_state distinguishes missing/invalid. Data-quality tables contain multiple runs;
filter the matrix to reports/latest_run.json run_id. No credentials belong in query source.

M and DAX have undergone source review only; a Power BI engine is unavailable here. Connector
installation and privacy settings may depend on the local Power BI Desktop build. Use Power BI's
own driver prompt if required and record the actual result rather than assuming refresh worked.

For the actual selected port and timestamped CSV folder, use POWER_BI_CONNECTION.json generated by the Windows workflow. Create the connection-only scalar query LatestSuccessfulRun before data_quality_results. It filters DQ to the latest successful run automatically.
