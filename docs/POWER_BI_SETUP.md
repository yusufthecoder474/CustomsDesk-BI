# Power BI Desktop setup — NOT YET VERIFIED IN POWER BI DESKTOP

The source package contains executable M definitions, DAX source, exports, a report theme and visual
field mappings. It does not contain a fabricated PBIX, an executed Power BI report, or a screenshot
presented as Power BI evidence. Build the three pages locally on Windows.

1. Install Power BI Desktop and run the Python demo from README. For PostgreSQL, run scripts/finish_windows.cmd and use the generated POWER_BI_CONNECTION.json. CSV fallback needs no database driver.
2. Open a blank report → Transform data. Create text parameters from powerbi/parameters.md.
3. Create blank query fxLoad, paste powerbi/fxLoad.m in Advanced Editor. Create named table queries
   with each matching .m file. Enable load for the seven warehouse tables plus run/DQ tables.
   Aggregate vw_* and rejected_records can stay connection-only unless used for validation/detail.
4. Review every Applied Step and error count. Keep HS codes and identifiers as text. Dates are Date;
   timestamps become UTC Date/Time without a local-zone shift; durations are Decimal Number;
   flags are True/False. Do not auto-convert HS codes to numbers. Close & Apply.
5. Model relationships, all **one-to-many, single direction from dimension to fact**:

| One side | Many side | Active |
|---|---|---|
| dim_part.part_id | fact_shipment.part_id | Yes |
| dim_part.part_id | fact_customs_query.part_id | Yes |
| dim_country.country_code | fact_shipment.origin_country | Yes |
| dim_country.country_code | fact_customs_query.country_code | Yes |
| dim_country.country_code | fact_shipment.destination_country | No |
| dim_authority.authority_id | fact_customs_query.authority_id | Yes |
| dim_query_type.query_type | fact_customs_query.query_type | Yes |
| dim_date.date_key | fact_shipment.dispatch_date | Yes |
| dim_date.date_key | fact_customs_query.opened_date | Yes |
| dim_date.date_key | fact_customs_query.closed_date | No |
| etl_run_log.run_id | data_quality_results.run_id | Yes |

6. Disable automatic fact-to-fact relationships, especially shipment_id. Mark dim_date as date table
   using date_key; verify continuity. Add a calculated column `YearMonth = FORMAT(dim_date[date_key], "yyyy-MM")`
   and use it for calendar month axes. No bidirectional filtering.
7. Add measures individually in powerbi/measures.dax order; format % measures as percentages,
   hours/days to two decimals and counts as whole numbers. Use docs/DAX_MEASURES.md and powerbi/MEASURE_EXPECTATIONS.csv to validate.
8. Import powerbi/theme.json via View → Themes → Browse. Build all three pages using
   powerbi/REPORT_LAYOUT.md. Display SYNTHETIC DATA and fixed cutoff on every page.
9. Reconcile unfiltered cards to data/exports/vw_kpis.csv. Use data/exports/vw_monthly.csv to
   verify monthly closures and MoM. For DQ matrices filter to latest successful run ID from
   reports/latest_run.json; DQ Pass Rate measure already filters that run.
10. Test country, authority, priority and month interactions; distinguish parts-current-state and
    DQ-run metrics from operational facts. Refresh after rerunning ETL/export.
11. File → Save As → CustomsDesk-BI.pbix. Keep local paths/credentials out of public screenshots.
    Record Power BI version, refresh date and validation outcomes in reports/POWER_BI_VALIDATION.md.
